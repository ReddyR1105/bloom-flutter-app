Before you choose

Equal complexity is built into every brief.
All nine use the same complexity contract and same pathway rubric. The mandatory core is five screen roles, two related entities with full CRUD for both, one start/progress/finish/reset workflow, one filter/aggregate, SharedPreferences settings, covered widgets and controls, one required local smart helper, and common offline/restart/error/two-device verification.

Feature suggestions: choose presentation details that serve your user, not every idea on the page. Visual polish is optional; one local smart helper is required for both pathways. Select one suggested feature, not every idea, and label rules or ML accurately. Each page offers the same depth: concept, five-screen map, six feature pillars, two-entity data model, integrity challenge, required helper recipe, separate undergraduate/graduate implementation, and demo evidence.

No cloud-based app storage or services. No Firebase, cloud authentication, live feeds, remote inference, or online multiplayer. Use small bundled datasets and on-device records. These briefs take structural inspiration from the supplied full-build reference, not its cloud stack, dates, or larger feature scope.

Modern ideas / manageable builds

A little intelligence. A visible benefit.
Each topic has a required beginner smart-helper recipe in its full brief: local inputs, a small method, a worked example, a visible benefit, and a test. Make one helpful suggestion in an existing screen rather than building a chatbot or growing the project scope.

Predict something small
Budget Bites estimates a meal cost; Habit Mastery suggests a realistic weekly target; Adaptive Focus suggests a session length; Trail Tales compares planning-time estimates.

Recommend a next choice
Campus Challenge picks a mission; Festival Pocket ranks local events; Movement Quest suggests a user-entered plan by equipment preference, not health needs.

Keep the mystery moving
Puzzle Companion and Midnight Manor choose prewritten hints that are relevant without spoiling the answer. Students can test whether their helper is useful, not just impressive-looking.

Beginner-friendly: rules and averages introduce the smart-helper workflow, but are not trained models. For a small machine-learning experience, recommendation topics can optionally try a nearest-neighbor matcher using a handful of fictional labeled examples. Keep calculations local, explain the method honestly, and let users ignore or override it.

Try the beginner AI walkthrough
One helper per team is required for full base credit. Undergraduates use a baseline and five case types; graduates also compare at least five held-out valid cases. Both document critical-thinking decisions in AI_FEATURE.md. Choose from the shared feature menu; no trained model or cloud service is required.

Choose your implementation pathway

One topic, clearly separated academic expectations.
Undergraduate implementation
Complete the shared five-screen, two-entity local CRUD app. Demonstrate widgets, controls, state, lifecycle cleanup, settings, filtering, aggregation, offline testing, and a peer-tested revision. Every topic brief has a dedicated undergraduate implementation section.

Undergraduate rubric / 100 points
Graduate implementation
Complete the same core plus advanced state management, UI/domain/data architecture with repository and dependency injection, automated tests and coverage, animations, background processing, local notifications, and file operations. Every brief has a separate graduate implementation section.

Graduate rubric / 100 points
Mixed-level teams: identify each member's pathway and contribution evidence. Graduate extensions are mandatory for graduates, not for undergraduates. Visual polish remains optional. The local helper, baseline, evaluation, and AI_FEATURE.md are required for both pathways; an AI coding assistant is optional.
