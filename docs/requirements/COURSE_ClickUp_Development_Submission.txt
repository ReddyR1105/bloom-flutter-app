🌿 Step 2: Branch Management
Main Branch: Keep stable, production-ready code
Feature Branches: Create new branch for each feature
Naming Convention: Use descriptive, lowercase names with hyphens
Regular Sync: Pull from main regularly to avoid conflicts

✓ feature/meal-editor

💬 Step 3: Commit Messages
Be Specific: Describe what changed and why
Use Present Tense: "Add feature" not "Added feature"
Start with Verb: Add, Fix, Update, Remove, Refactor
Keep it Short: 50 characters for title, detailed explanation in body if needed
✅ Good Commit Examples

📋
Copy
✓ "Add meal editor with local price validation"
✓ "Fix database connection bug in DatabaseHelper"
✓ "Update README with installation instructions"
✓ "Implement dark mode theme switching"
✓ "Refactor item list widget for better performance"
✓ "Remove deprecated sqflite methods"
✓ "Add unit tests for database operations"
✓ "Fix navigation bar overflow on small screens"
❌ Bad Commit Examples

📋
Copy
✗ "update" (what was updated?)
✗ "fix bug" (which bug?)
✗ "changes" (what changes?)
✗ "asdfasdf" (meaningless)
✗ "final version" (not descriptive)
✗ "working now" (what is working?)
✗ "..." (empty message)
✗ "stuff" (too vague)

🔀 Step 6: Pull Requests
Create PR: On GitHub, click "New Pull Request" for your branch
Write Description: Explain what the PR does and why
Request Review: Tag team members for code review
Address Feedback: Make requested changes and push updates
Merge: After approval, merge into main branch
💡 Pull Request Best Practices:

• Include screenshots for UI changes
• Link to related issues or tasks
• Test thoroughly before requesting review
• Keep PRs focused (one feature per PR)
• Respond to review comments promptly
